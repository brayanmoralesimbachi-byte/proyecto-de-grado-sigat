🗄️ Base de Datos Cifrada

SQLite + SQLCipher con cifrado AES-256 para proteger todos los datos en reposo.

🔑 Hash Seguro de Contraseñas

Argon2id - ganador del Password Hashing Competition. Las contraseñas nunca se almacenan en texto plano.

🌐 Sin Exposición de Red

Aplicación 100% local, sin servidores HTTP ni APIs expuestas. No abre puertos ni expone servicios.

Registro completo e inalterable de todas las operaciones del sistema para trazabilidad total.

🚀 Comandos de Desarrollo

Guía completa de comandos disponibles para el desarrollo y despliegue de la aplicación:

📦

npm install

Propósito: Instalar todas las dependencias del proyecto.

¿Qué hace? Lee el archivo package.json y descarga todas las librerías necesarias (Angular, TypeScript, herramientas de desarrollo, etc.) al directorio node_modules/. Debe ejecutarse al clonar el proyecto por primera vez o cuando se actualice el package.json.

Cuándo usarlo: Primera vez que configuras el proyecto o después de un git pull que incluya cambios en dependencias.

npm install
🔧

npm run dev

Propósito: Ejecutar la aplicación en modo desarrollo.

¿Qué hace? Inicia el servidor de desarrollo de Angular con recarga automática (hot-reload). Cualquier cambio que hagas en el código se reflejará instantáneamente sin necesidad de reiniciar. El frontend se conecta al backend Rust para desarrollo.

Características:

  • Hot-reload automático para cambios en frontend
  • Mapas de código fuente para debugging
  • Mensajes de error detallados en consola
  • No optimizado (más rápido de compilar)
npm run dev
▶️

npm start

Propósito: Iniciar la aplicación Angular.

¿Qué hace? Ejecuta el servidor de desarrollo de Angular. Similar a npm run dev pero con la configuración estándar de Angular CLI.

Puerto por defecto: http://localhost:4200

npm start
🦀

npm run tauri dev

Propósito: Ejecutar la aplicación completa en modo desarrollo (Frontend + Backend).

¿Qué hace? Inicia simultáneamente:

  1. El servidor de desarrollo de Angular (frontend)
  2. Compila y ejecuta el backend Rust con Tauri
  3. Abre la ventana de la aplicación de escritorio

Características:

  • Hot-reload completo (frontend y backend)
  • DevTools disponibles en la ventana
  • Logs de Rust visibles en terminal
  • Comunicación en tiempo real Angular ↔ Rust

Nota: Requiere Rust instalado y configurado correctamente.

npm run tauri dev
📦

npm run tauri build

Propósito: Compilar la aplicación para producción.

¿Qué hace? Realiza una compilación completa optimizada:

  1. Compila Angular en modo producción (minificado, tree-shaking)
  2. Compila Rust en modo release (optimizaciones máximas)
  3. Empaqueta todo en un ejecutable nativo
  4. Genera instaladores para el sistema operativo

Salida (Windows):

  • Ejecutable: src-tauri/target/release/gestor-activos.exe
  • Instalador MSI: src-tauri/target/release/bundle/msi/

Tiempo aproximado: 3-10 minutos dependiendo del hardware.

npm run tauri build
🧪

npm test

Propósito: Ejecutar las pruebas unitarias del proyecto.

¿Qué hace? Ejecuta el framework de testing (Karma/Jasmine por defecto en Angular) para correr todos los archivos *.spec.ts. Valida que los componentes y servicios funcionen correctamente.

Archivos de test: src/app/**/*.spec.ts

npm test
🛡️

npm run test:security:frontend

Propósito: Ejecutar la suite de seguridad del frontend (Angular + Vitest).

¿Qué hace? Corre pruebas de autenticación, control de acceso por guard, chatbot, validaciones de subida de archivos y umbrales de rendimiento en frontend.

Archivos de test: tests/frontend/**/*.spec.ts

npm run test:security:frontend
🦀

npm run test:security:backend

Propósito: Ejecutar la suite de seguridad del backend Rust.

¿Qué hace? Ejecuta pruebas de criptografía, gestión de clave local, inicialización segura de base de datos/auditoría y límites de rendimiento en operaciones críticas.

Comando interno: cargo test --test security dentro de src-tauri/.

npm run test:security:backend
📊

npm run test:security:ci

Propósito: Ejecutar frontend + backend de seguridad en cadena con resumen final para CI/CD.

¿Qué hace? Lanza ambas suites, mide tiempo por bloque y muestra estado PASS/FAIL de cada una en un resumen consolidado.

Script: scripts/security-ci.mjs

npm run test:security:ci

🤖 Chatbot NLP - Asistente Virtual Inteligente

Sistema de búsqueda inteligente mediante lenguaje natural en español, con extracción automática de filtros y respuestas contextuales.

Búsqueda de Activos

🔍 Filtros Soportados

  • Código: Búsqueda exacta con prioridad máxima
  • Marca: LG, Samsung, Dell, HP, Lenovo, Apple, etc.
  • Categoría: Equipos, telecomunicaciones, mobiliario, herramientas, software
  • Estado: Operativo, en mantenimiento, fuera de servicio, en reparación
  • Ubicación: Facatativá, Bogotá, Medellín, Cali, etc.
  • Precio: Más de, menos de, entre (ej: "menos de 50000")

📏 Medidas Específicas por Categoría

  • Pulgadas: Para monitores y TV (ej: "monitor de 24 pulgadas")
  • Calibre: Para armas (ej: "arma de 9mm", ".45")
  • Litros: Para líquidos (ej: "leche de 2 litros", "500ml")
  • Peso: Para alimentos (ej: "arroz de 5 kg", "2 libras", "500 gramos")

🧠 Inteligencia de Filtrado

  • Filtros se aplican siempre, incluso con 0 resultados
  • Detección de búsquedas vagas (< 4 caracteres)
  • Stopwords ignoradas: el, la, un, de, en, con, etc.
  • Prioridad: código > marca/categoría/estado > keywords
  • Prevención de falsos positivos con word boundaries

Búsqueda de Auditorías (Admin)

👤 Por Usuario

Filtrar registros por nombre de usuario:

  • "registros de admin"
  • "actividades de jose"
  • "dame todos los registros del usuario admin"

⚡ Por Acción

Filtrar por tipo de evento:

  • LOGIN / LOGOUT
  • CREATE / UPDATE / DELETE
  • "muestra los logins de admin"

📤 Exportación Inteligente

Exportar registros con filtros aplicados:

  • Todos los datos o solo resultados visibles
  • Filtrar por rango de fechas
  • Filtrar por categorías (LOGIN, LOGOUT, etc.)
  • Respeta filtros de usuario y acción de la búsqueda
  • Formatos: PDF y XML

Ejemplos de Consultas


✅ "busco un monitor LG de 24 pulgadas en Facatativá"
   Filtros aplicados: marca=LG, pulgadas=24, ubicacion=Facatativá

✅ "femb de menos de 50000 en operativo"
   Filtros aplicados: keywords=femb, precio_max=50000, estado=operativo

✅ "arma de 9mm en Bogotá"
   Filtros aplicados: calibre=9mm, ubicacion=Bogotá

✅ "arroz de 5 kg"
   Filtros aplicados: keywords=arroz, peso=5, unidad_peso=kg

✅ "código 123456"
   Búsqueda exacta por código (prioridad máxima)

✅ "registros de admin" (admin only)
   Filtros aplicados: usuario=admin

❌ "lg" (búsqueda vaga, < 4 caracteres)
   Respuesta: "Tu búsqueda es muy vaga..."

❌ "código 999999" (no existe)
   Respuesta: "No tenemos el código 999999 en nuestro inventario"

Casos Especiales

⚠️ Manejo de Excepciones

  • Código inexistente: Mensaje específico indicando que no existe
  • Búsqueda vaga: Solicita keywords más específicos (min 4 caracteres)
  • Sin coincidencias: Sugiere ampliar criterios o verificar ortografía
  • Prevención de falsos positivos: "alguno" NO detecta marca "LG" (word boundaries)
  • Orden de extracción: "2 kg" NO se detecta como "2 g" (kg antes de g)

🗂️ Asignaciones - Bases de Datos Lógicas

Sistema de segmentación de activos por bases de datos lógicas, permitiendo que cada unidad/departamento gestione sus propios activos de forma aislada dentro de la misma aplicación.

📋 Gestión de Bases de Datos

➕ Crear Base de Datos

El administrador puede crear bases de datos lógicas con nombre y descripción, representando unidades, departamentos o sedes.

👥 Asignar Usuarios

Cada usuario (operador/auditor) puede ser asignado a una o varias bases de datos. Los administradores ven todas.

🔒 Aislamiento de Datos

Los usuarios no administradores solo ven activos, auditorías y logs de las bases de datos a las que están asignados.

⛔ Sin Base Asignada

Si un usuario no tiene bases asignadas, se le muestra una pantalla informativa bloqueando el acceso hasta que el administrador lo asigne.

🛡️ Protección al Eliminar

No se puede eliminar una base de datos que tenga activos asociados. El sistema muestra un mensaje con la cantidad de activos bloqueantes.

📤 Exportar / Importar

Exporta cualquier base de datos a un archivo ZIP cifrado con AES-256. Se genera una contraseña aleatoria de 30 caracteres que se muestra al usuario con opción de copiar. Importa desde ZIP: verifica admin password, selecciona archivo, ingresa la contraseña de exportación, y crea una nueva base de datos con todos los activos y re-asignación de usuarios.

📊 Filtro por Base

Los usuarios con múltiples bases pueden filtrar activos y auditorías por base de datos mediante un dropdown.

🔒 Control de Acceso Basado en Roles (RBAC)

Sistema de permisos granular que define qué puede hacer cada tipo de usuario:

👑 Administradores

  • Ver historial de visualizaciones - Quién y cuándo vio cada activo
  • Ver logs de LOGIN/LOGOUT - Eventos de autenticación completos
  • Filtrar por LOGIN/LOGOUT - Filtros especiales en auditoría
  • Gestionar usuarios - Crear, modificar y eliminar
  • Asignar roles - Promover o degradar usuarios
  • Acceso completo - Todas las funcionalidades

👤 Usuarios Regulares (Operador / Auditor)

  • CRUD de activos - Crear, leer, actualizar, eliminar
  • Ver auditoría limitada - Solo CREATE, UPDATE, DELETE
  • Gestionar su perfil - Cambiar contraseña, zona horaria
  • Búsqueda y filtros - Acceso completo a búsquedas
  • Dashboard - Estadísticas y vista de activos
  • Segmentación por base de datos - Solo acceden a activos y auditoría de sus bases asignadas

🔧 Implementación Técnica

// En componentes con restricciones
isAdmin(): boolean {
  return this.authService.hasRole('admin');

// En templates Angular

  );
}

💻 Uso Básico desde Angular

Ejemplo de cómo interactuar con el backend Rust desde el frontend Angular:

import { TauriService } from './services/tauri.service';

// Inyectar el servicio
constructor(private tauriService: TauriService) {}

// Obtener activos
const activos = await this.tauriService.getActivos();

// Login de usuario
await this.tauriService.login(username, password);

// Obtener detalles de un activo
const detalles = await this.tauriService.getActivoDetalles(activoId);

// Registrar visualización
await this.tauriService.registerActivoVista(activoId, userId);

⚠️ Notas Importantes

🔑 Clave de Cifrado

La clave de cifrado de la base de datos debe derivarse de credenciales válidas del usuario en producción. El ejemplo actual usa una clave temporal solo para desarrollo.

🔐 Gestión de Claves

Se recomienda implementar un sistema de gestión de claves maestras para el entorno de producción.

📂 Almacenamiento

La base de datos se almacena en el directorio de datos de la aplicación, protegida a nivel del sistema operativo.

🦀 Requisitos Rust

Para compilar el backend, se requiere tener Rust instalado con las herramientas de compilación de Windows (MSVC).
